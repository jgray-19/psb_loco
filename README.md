# psb_loco — PSB ring-3 LOCO by two independent methods

Recover **individual quadrupole `k1` errors** in PSB ring 3 by matching the model's
corrector orbit-response to the one measured by the 2026-08-21 scan (six DHZ and
six DVT correctors, each stepped through `offset_k = 0, ±dk, ±2dk` with
`DELTA_K = 5e-5`, under five RF-steering offsets).

That scan was run twice, at two quadrupole powerings — the "normal" tunes
(measured 4.1711 / 4.2294) and the "inverted" ones (4.2335 / 4.1279), with the
correctors untouched between them. Both are in `loco_common/campaign.py`; every
script that reads the measurement takes `--campaign {normal, inverted,
inverted_double}` and defaults to the first, which is what every published number
predating the second configuration was fitted on.

The start model is **never tune-matched**: its two main quadrupole circuits are
the machine's own LSA readings, so its tune disagrees with the measured one on
purpose — matching would move exactly the circuits a distributed gradient error
moves. `scripts/measured_optics.py` measures the gap from the MD's AC-dipole
acquisitions and the tune/chroma scan, and twisses both lattices — un-matched and
matched to the measured tune — so the cost of not matching is a number rather
than an argument. `docs/studies/measured-optics.md` is the result.

**Picking this up cold? Read [docs/reference/handover.md](docs/reference/handover.md) first** — settled
conventions, open problems in priority order, and the traps that cost time.

Two methods, two folders. They share no solver and no objective, which is the
point: agreement between them is the acceptance evidence. Neither method's own
residual is a quality score and nothing here reports it as one.

| | Method 1 (`method1_madng_da/`) | Method 2 (`method2_delta_orbit/`) |
|---|---|---|
| fits | `d(orbit)/d(k)` — the response matrix | `co(k+dk) − co(k)` — delta closed orbits |
| how | first-order DA builds the full response matrix | one MAD-NG worker per corrector setting, gradients summed |
| solver | `MAD.match`, numerical derivative of matrix-cell equalities | Levenberg-Marquardt Gauss-Newton (`aba_optimiser.ClosedOrbitFitter`) |
| free knobs | native 32 cell-grouped quadrupole `dk1l` knobs | 48 per family, or 32 with native cell grouping |

## Layout

```
loco_common/        measured_response.py  naming.py  momentum.py  model.py
method1_madng_da/   response_da.mad  run_method1.py
method2_delta_orbit/run_method2.py  PSB measurement preparation and CLI
tests/              pytest; truth generated by xsuite via xtrack-tools
```

`psb_md`, `aba_optimiser`, `tmom_recon` and `xtrack_tools` are imported as
installed packages. The reusable closed-orbit worker and fitter are in
`aba_optimiser`; this repository contains no local optimisation implementation.

## Running

```bash
source ../accpy/bin/activate
python -m method1_madng_da.run_method1 --rf-offset 0
python -m method2_delta_orbit.run_method2 --rf-offset 0 --output results/method2
python -m method2_delta_orbit.run_method2 --campaign inverted --output results/method2_inverted
python compare_fits.py   # every results/*/knobs.csv against the measurement
```

`--sequence-file` is currently required; see docs/reference/handover.md §2.

Method 2 also takes `--correctors`, `--offsets`, `--rf-offsets` and
`--batch-momenta`. `--rf-offsets` enables the multi-momentum mode (see the caveat
below); `--batch-momenta` fits every momentum of a corrector trim in one MAD-NG
process instead of one per (trim, momentum), which is what keeps the process
count under the ceiling documented below. The two runs the results table's new
rows come from:

```bash
python -m method2_delta_orbit.run_method2 --rf-offset 0 \
    --output results/method2_1pt_allsteps
python -m method2_delta_orbit.run_method2 --rf-offsets -2 -1 0 1 2 --batch-momenta \
    --output results/method2_lumped_5pt_allsteps
```

Both take every corrector step the scan holds, which is the default; `--offsets`
narrows that. Note that argparse only accepts a negative step written in decimal,
`-0.0001` rather than `-1e-4`.

`--group-quadrupoles-by-cell` selects the PSB's native 32-knob parameterisation
for every enabled per-quadrupole family. In each of the 16 cells the two QFO
magnets share one knob and the QDE remains independent. The shared knobs are
created directly in MAD-NG; there is no solver-side projection and no partial-
family or 16-knob mode.

## The three things worth knowing

**One equality per matrix cell.** Method 1 builds a `(2*N_BPM) x N_corrector`
matrix: all horizontal BPM channels, then all vertical channels. A first-order
DA twiss produces every `d(orbit)/d(kick)` cell at once. Each cell becomes one
`MAD.match` equality with its own measured target and inverse-error weight;
MAD.match finite-differences those equalities with respect to the 32 native
cell-grouped `dk1l` knobs. No second-order DA or per-magnet conversion remains.

**One reference orbit for the whole scan.** Everything — every corrector step,
every RF-steering offset — has the *same* orbit subtracted: the untrimmed machine
at nominal RF (`global_reference_orbit`). Referring each RF setting to its own
untrimmed orbit would subtract that momentum's dispersion away, and dispersion is
quadrupole-sensitive signal the multi-momentum mode exists to fit. Method 1's
slopes do not care (its fit keeps the intercept free, so any constant reference
cancels); Method 2's targets do, and the model side matches it by taking its
reference at `pt = 0`, not at the worker's own momentum. The off-momentum
untrimmed orbits, which used to be identically zero, now enter as one extra
worker per RF setting carrying pure dispersion.

**The delta is subtracted in the model, not only in the data.** The targets
handed to Method 2 are already differences, but the free quadrupoles move the
*nominal* orbit too. `aba_optimiser.ClosedOrbitWorker` therefore re-runs the closed twiss at the
reference state every iteration and differences both the orbit and its Jacobian.
Subtracting a once-computed reference would leave `J_0`'s quadrupole dependence
in the residual.

**Momentum calibration is explicit.** Multi-momentum fits retain the original
orbit-projected calibration by default (`--momentum-source orbit`); the independent
RF/XImeter calibration is available as `--momentum-source chroma`. The former uses
the starting model dispersion while the latter converts the measured `Dp/p` bands.
Both mappings are converted to MAD-NG `pt` before subtracting the nominal-RF
reference, and both are logged in each fit's `summary.json`. Neither source is
treated as validated until the controlled method-6 comparison is complete.
The completed convention audit and A/B results are in
[`docs/studies/momentum-calibration.md`](docs/studies/momentum-calibration.md).

Two smaller ones: LSA's `/K` is taken to be the kick angle in rad
(`LSA_K_TO_RAD = 1.0`, pinned against xsuite in `tests/test_naming.py`), and the
multi-momentum mode's `pt` values are **estimated** from the dispersive orbit,
not known — a wrong `pt` is a bias in the fit rather than noise, which is why
that mode is opt-in. With the global reference that bias bites harder than it
used to: a 20% error visibly degrades the recovered gradients
(`tests/test_pt_mode.py`) and a sign error walks the quadrupoles into an unstable
lattice, where MAD's normal form fails outright rather than returning a bad
answer.

## What the 2026-08-21 data says

Run on the real RF-offset-0 scan, 48 free quadrupoles, response error relative
to the measured response:

| fit | settings | processes | response error | weighted |
|---|---|---|---|---|
| start model | | | 15.5 % | 176 σ |
| Method 1, 12 correctors | | | 12.4 % | 141 σ |
| **Method 2, 12 correctors, all 4 steps** | 48 | 48 | **8.8 %** | **98 σ** |
| Method 2, 12 correctors, 1 step | 12 | 12 | 9.1 % | 103 σ |
| Method 2, 12 correctors, 1 step, 5 momenta | 64 | 64 | 10.8 % | 124 σ |
| Method 2, 12 correctors, 1 step, 5 momenta, lumped | 64 | 13 | 10.8 % | 124 σ |
| Method 2, 12 correctors, all steps, 2 momenta, lumped | 97 | 49 | 10.8 % | 126 σ |
| Method 2, 12 correctors, 1 step, 3 momenta | 38 | 38 | 11.0 % | 127 σ |
| Method 2, 12 correctors, all steps, 5 momenta, lumped | 244 | 49 | 11.0 % | 127 σ |
| Method 2, 12 correctors, all steps, 4 momenta, lumped | 195 | 49 | 11.2 % | 130 σ |
| Method 2, every acquisition in the scan, lumped † | 292 | 61 | 11.4 % | 132 σ |
| Method 2, 12 correctors, all steps, 3 momenta, lumped | 146 | 49 | 11.5 % | 133 σ |
| Method 2, 12 correctors, 2 steps, 5 momenta | 124 | 124 | 11.5 % | 133 σ |
| Method 2, 12 correctors, all steps, 3 momenta, duplicates kept † | 170 | 170 | 12.1 % | 141 σ |
| Method 2, 4 correctors, 1 step | 4 | 4 | 17.4 % | 192 σ |
| Method 2, 4 correctors, 1 step, 3 momenta | 14 | 14 | 42.0 % | 538 σ |

† weights each momentum's untrimmed orbit twelvefold, by keeping the twelve
per-corrector copies of it rather than the average. That was the default until
now; these two rows are what it cost. Their deduplicated counterparts are the
146- and 244-setting rows above, 0.6 and 0.4 points better.

Eight things to take from that.

**Lumping the momenta changes nothing but the process count.** The 5-momentum,
1-step fit run as 64 processes and as 13 (``--batch-momenta``) agree to **5e-12
relative** on every one of the 48 knobs, and their uncertainties to 2e-12. That
is the same objective summed in a different place, not two fits that happen to
land close, and it is what makes the whole-scan rows runnable at all -- every
corrector, every step, every momentum, 244 settings in 49 processes, or 292 in 61
with the duplicates: the unlumped layout would need one process per setting and
dies at about 250.

**Every corrector step, at one momentum, is the best fit yet: 8.8 %.** All four
LSA steps (+-5e-5, +-1e-4) rather than the single +1e-4 the 9.1 % row uses, and
the first configuration to agree with Method 1 at **+0.987** on the response
change (against +0.968 before). The gradients it asks for are no more physical
than before -- 6.6 % rms, 19 of 48 past 5 %, 8 past 10 % -- so this is still the
per-corrector gain of the next section being absorbed into shape parameters, but
it is the cleanest single-momentum answer the scan supports.

**More scenarios stop helping once the momenta are in.** With the descriptor
ceiling lifted, every corrector setting was run against one to five momenta --
the whole grid, for the first time. Response error against momentum count, all
four corrector steps throughout: **8.8, 10.8, 11.5, 11.2, 11.0 %**. It is flat
from two onward to within the spread of the set, and the fits themselves are the
same fit: the 4- and 5-momentum gradients correlate at **+0.998**, 3 against 5 at
+0.990, 2 against 5 at +0.962. Adding momenta past two moves nothing; the only
step in the sequence is the first one, and it goes the wrong way.

**The momenta cost something rather than nothing, and it is the model's
dispersion.** One momentum with every step is 8.8 %; two is 10.8 %. That is not
under-constraint -- 97 settings against 48 -- and it is not the lumping, which is
exact to 5e-12. It is what §"the model's dispersion is still wrong" below
describes: the off-momentum targets carry a dispersion error worth 40-90 σ that
no quadrupole can absorb, so each momentum added drags the fit further from the
on-momentum response it is scored against. The multi-momentum fits are still the
better-conditioned ones (4.2-4.5 % rms gradient change against 6.6 %), which is
the tension to hold: they ask less of the quadrupoles, and reproduce the measured
response less well, because they are being asked to fit dispersion the model does
not have.

**The zero-corrector acquisition per momentum is in the fit, once -- and that
is now the default.** At each non-zero RF setting the scan holds twelve
``offset_k = 0`` acquisitions: the same untrimmed machine, recorded once per
corrector. ``build_multi_pt_settings`` averages them into a single
``(dispersion)`` setting and drops the twelve individually, which is why the
momentum runs log **13** correctors and why 244 = 12 x 4 x 5 + 4. At
``rf_offset = 0`` there is none, correctly: that acquisition *is* the global
reference.

Passing the twelve through individually weights that one orbit twelve times over,
and until now it was the default -- ``--offsets`` was the only thing that
suppressed them, which is why the older multi-momentum rows carry settings counts
nobody chose. ``--keep-zero-step-duplicates`` restores the old behaviour for
comparison. The two daggered rows are that comparison. The first is every
acquisition in the scan, 292 settings -- the exact configuration this README used
to record as dying at worker 261 -- now 61 processes: **11.4 %**, against 11.0 %
for the same data deduplicated, the two agreeing at **+0.996** on the gradients.
The second is the old 3-momentum, all-steps run: **12.1 %**, against **11.5 %**
deduplicated. The duplication costs half a point and buys nothing.

The same change makes ``--no-dispersion-workers`` mean what it says. It used to
drop the averaged setting while leaving twelve copies of the same orbit in the
fit, so it never removed the dispersion constraint it was written to isolate.

One detail in that averaging is wrong in a way worth knowing: it is
``sum(frames) / len(frames)``, which averages the *error bars* along with the
orbits, giving ``err_mean = mean(err)`` where the average of twelve deserves
``err/sqrt(12)``. The dispersion setting therefore enters with an error bar about
3.5x too large, i.e. under-weighted roughly twelve-fold. Given that the model's
dispersion is itself wrong (below), that is accidentally protective -- but it is
not deliberate, and anyone fixing the dispersion should fix this first or the
weight will jump by an order of magnitude underneath them.

**The two methods agree where the fit is well posed.** At 12 correctors the
response changes they make correlate at +0.97, and their gradient corrections at
+0.92, from different solvers and different objectives. That agreement is the
acceptance evidence; neither residual is a quality score.

**Method 2 does not bound its knobs, and is not going to.** The per-magnet
Method 1 that preceded the 32-knob one bounded its variables at 5 %, because
``MAD.match`` walked the lattice into a stop band without it; neither method
bounds anything now. Method 2's Levenberg-Marquardt solve has no such bound: the isotropic prior is what keeps it in range, and the knob counts
``compare_fits.py`` prints -- ``past 5%: N/48``, and ``--bounds 0.05 0.10`` for
any other threshold -- are a *reading* of the answer, not a limit it respected.
Read them as the symptom they are: at 10 % the single-momentum fits still put 6-8
knobs beyond any gradient error a real PSB quadrupole has, which is the corrector
gain of the next section arriving in the only parameters the fit has.

**Four correctors is not enough for 48 knobs.** The 4-corrector fit is *worse*
than the starting model and puts 20 of 48 gradients beyond 5% of nominal. Use the
full corrector set.

**The multi-momentum mode is roughly a wash at 12 correctors, and its
catastrophic 4-corrector number was under-constraint, not momentum.** Read the
table in pairs: at 4 correctors the extra momenta take the fit from 17.4 % to
42.0 %, but at 12 they take it from 9.1 % to 11.0 %. The mode is not what breaks
the 4-corrector fit -- too few constraints for 48 knobs is, and the off-momentum
data merely gives an already under-determined fit more room to go wrong.

**Momentum saturates at three.** Going from 3 RF settings to all 5 moves the
answer by nothing that matters: 11.0 % -> 10.8 %, gradient corrections identical
to 4.1 % rms, and the two fits agree with each other at **+0.997** on the
response change they make. Adding corrector steps on top is likewise flat
(11.5 % at 2 steps, 11.5 % at all steps with 3 momenta). Three momenta and one
step is the cheap point on that curve.

That 11.0 % is also scored against a handicap worth stating: the single-momentum
fit is being measured on exactly the data it fitted, while the multi-momentum fit
is measured on one third of its own. On the constraint it shares, the two land
close, and the multi-momentum fit is the better-conditioned of the two -- 4.1 %
rms gradient change with 10 of 48 knobs past 5 %, against 6.2 % and 17
of 48 for single-momentum. Adding every corrector step (146 settings rather than
38) does not improve it further: 11.5 %, within the spread of the pair.

**The model's dispersion is still wrong, which is what caps the gain.** The
momentum estimates are sound -- ``tmom_recon`` and a direct dispersion projection
agree to the displayed digits, and dropping the dispersion workers changes
nothing (42.0 % -> 41.1 % at 4 correctors). What does not agree is the dispersion
itself: against the measurement the residual is 79-84 % of the measured amplitude
horizontally and **108-110 % vertically** (the machine has 7.7e-5 m rms of
vertical dispersion where the model has 2.0e-5 m). Under the global reference
that error enters every off-momentum target as a first-order term worth 40-90 σ.
``--rf-offsets`` is usable with the full corrector set, but it will not pay for
itself until that is fixed.

**There is a hard ceiling on worker count, at about 250.** ``pymadng`` waits on
each MAD process with ``select()`` (``madp_pymad.py:124``), and ``select()``
rejects any file descriptor numbered at or above ``FD_SETSIZE`` = 1024. 170
workers start; 292 -- 12 correctors x 5 steps x 5 momenta -- dies at worker 261
with ``ValueError: filedescriptor out of range in select()``. Raising
``ulimit -n`` does not help, because the limit is on the descriptor's *number*,
not on how many are open. Lifting it means moving ``pymadng`` to ``poll()``,
which is upstream.

``--batch-momenta`` uses one MAD-NG
process per corrector *trim*, fitting every momentum that trim was measured at
inside it, so the process count is ``len(offsets) x len(correctors)`` with the
momentum factor removed. The objective is unchanged -- the same per-(trim,
momentum) losses are summed, inside a process rather than across processes, with
the same global normalisation -- and a batched worker also costs ``1 +
len(rf_offsets)`` parametric twisses per iteration rather than ``2
len(rf_offsets)``, because the reference twiss is shared. That equivalence is
pinned by ``tests/test_delta_worker.py``. Without it, keep ``len(rf_offsets) x
len(offsets) x len(correctors)`` under roughly 250.

**Still unmodelled:** per-corrector gain. The measured/model ratio runs 0.71-0.93
across the six DHZ against 0.95-1.03 for the six DVT, uniformly across all BPMs
for a given corrector. That is calibration, and no quadrupole gradient can
produce it -- a gradient error changes the *shape* of a corrector's response, not
its overall scale. A conventional LOCO frees corrector and BPM gains alongside
the quadrupoles; this one does not, by design.

## Tests

```bash
pytest              # fast set only
pytest -m ""        # everything, including MAD-NG and xsuite (~50 s)
```

The fake machine is built with xsuite and fitted with MAD-NG. Generating truth in
an independent code is deliberate: a convention error shared by model and data
would cancel out of the answer if one twiss produced both.
